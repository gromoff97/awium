## Цель

Искать и реализовывать упрощения, которые уменьшают общую сложность продукта и тестов.
Убирать лишние данные, состояния, правила, преобразования и дублирующие способы
сделать одну операцию. Сохранять короткий, понятный и типобезопасный fluent API.

Оценивать изменение вместе со всеми затронутыми компонентами и пользовательским
кодом. Перенос сложности из одного класса в другой не считается упрощением.
Сокращение строк или количества классов само по себе не является целью.

## Что искать

- Поля и параметры, которые можно вычислить из уже имеющихся данных.
- Несколько представлений одного состояния и код их синхронизации.
- Повторные разборы одного результата, лишние ветвления и преобразования.
- Обёртки и абстракции, не оправдывающие свою сложность.
- Дублирующие операции API, неиспользуемый и неактуальный код.
- Доказанные дефекты любого размера: подтверждать и исправлять их по ходу работы.

Исследовать всю кодовую базу. Для каждого кандидата установить, что именно
исчезает и что добавляется в соседних компонентах. Проверять, не защищает ли
существующая конструкция нужное поведение или вывод типов. Отклонять варианты,
которые сокращают один участок ценой усложнения остальных.

## Договорённости

- Публичный API и публичное поведение разрешено менять ради общего упрощения,
  в том числе когда прежнее поведение не было дефектом. Обратная совместимость
  и переходные алиасы не требуются. Сохранять философию: проверки выражаются
  через `Condition`, пользовательский код остаётся короткой, единообразной
  и типобезопасной fluent-цепочкой. Для одной операции оставлять один способ.
- Цепочка заканчивается на `until`, возвращающем конкретный тип. Каждый вид
  условия поддерживает `because`; `present` и `single` доступны без скобок.
  Сохранять вывод типов без явных generics в поддерживаемых цепочках, запрет
  несовместимых условий при компиляции и отсутствие случайного расширения до `Object`.
- В коллекциях `contains(value)` и `doesNotContain(value)` принимают ровно один
  элемент, включая список или массив. Готовый набор передаётся через
  `containsAll(collection)` и `doesNotContainAny(collection)`. Перегрузки varargs
  для этих двух одиночных операций и переходные алиасы не нужны.
- Для Map тот же принцип: `containsKey`, `doesNotContainKey`, `containsValue`,
  `doesNotContainValue` принимают один объект; методы keys/values во множественном
  числе, включая `containsOnlyKeys`, принимают коллекцию. Четыре дополнительных
  публичных метода согласованы пользователем ради единого контракта.
- `Condition` остаётся моделью и хранит собственные метаданные. Проверка возвращает
  `Satisfied` или `Unsatisfied`; `Uncontrolled` принадлежит результату попытки.
  `AwaitAttempt.probe` проверяет полученное наблюдение; `SequenceExecution`
  управляет этапами и не реализует `AwaitAttempt`.
- Ядро обрабатывает все `Throwable` единообразно. Адаптер `asserted` преобразует
  `AssertionError` в `Unsatisfied`. Выброшенный `InterruptedException` не требует
  восстановления флага; учитывается фактический флаг потока.
- Конкретные правила последовательностей, удержания результата, обработки `null`
  и диагностики можно пересматривать, если это уменьшает общую сложность
  и сохраняет философию API. Прежние тесты сами по себе не запрещают такое изменение.
  Конфигурация, условия и структуры опубликованных результатов остаются неизменяемыми;
  пользовательские объекты сохраняют свой тип и идентичность. Рабочее состояние
  локально выполнению.
- Java 21, без новых runtime-зависимостей. Имена параметров типов — капсом.
  README и Javadoc разрешено менять и синхронизировать с кодом.
  Скиллы Java-рефакторинга не применять.

## Рабочий цикл

1. Проверить текущее дерево и сохранить уже согласованные накопленные изменения
   отдельным исходным коммитом после проверки diff и результатов тестов.
2. Выбрать механизм, изучить его вызовы и потребителей результатов.
3. Сформулировать, какую общую сложность можно удалить. При сомнениях проверить
   небольшой прототип; не превращать неудачную идею в обязательную правку.
4. Сделать законченное изменение во всех затронутых местах. При изменении
   публичного поведения записать прежнее и новое правило, причину изменения
   и пример использования API. Проверить, что философия условий и цепочки сохранена.
5. Проверить поведение подходящими тестами и выполнить `git diff --check`.
   Положительные примеры типизации проверять реальным использованием API;
   отрицательные проверки несовместимых типов сохранить. Дефекты подтверждать
   воспроизводящими тестами. При намеренном изменении поведения обновить проверки
   под новый контракт. Не добавлять тесты, повторяющие реализацию.
6. При изменении общих правил исполнения, типизации или нескольких компонентов
   выполнить полный `./gradlew check`.
7. После успешных проверок сделать локальный коммит в `main` с понятным смыслом.
   Коммитить законченные изменения регулярно, не откладывая всё до утра.
   Push выполняется по отдельному указанию пользователя.
8. Кратко фиксировать результат, влияние на связанные компоненты, проверки
   и SHA коммита. Продолжать поиск, учитывая возможности новых упрощений,
   открывшиеся после изменения. Сообщать пользователю о ходе работы.

## Проверенные ограничения, которые остаются актуальными

- Acquisition и persistence принимают разные решения на границе времени.
  Их слияние в один цикл добавляло флаги и скрывало порядок проверок.
- Timing различает отсутствие наблюдения и наблюдение null. Плоская модель
  исходов или набор nullable-полей теряют эту границу либо скрывают состояния.
- Source views и их параметры элемента/ключа/значения сохраняют нужные bounds.
  Удаление этих осей давало Object или ошибки javac. Plain Callable wildcard
  не всегда выбирает специализированный вход. Рабочие варианты и ограничения
  описаны в README и закреплены фактическим использованием API.
- Отдельные capture-типы между наблюдениями важны для изменяемых Map.Entry.
  Typed view не даёт ошибочно связать значения двух разных wildcard-карт.
  `/tmp/awium-entry-capture-safety/report.json`.
- Target typing Java не проходит сквозь because к предыдущему generic-вызову.
  Для matches помогает method reference либо типизированный параметр lambda;
  для sorted — конкретный comparator вроде String::compareTo.
  Generic-сужение because позволяло несовместимые типы и отклонено.
- Проверки размера в сравнении — быстрый отказ до потенциально долгого обхода.
  Замена глубокого равенства на hashing меняет семантику массивов, асимметричного
  equals и вызовов пользовательских методов.
- SequenceExecution не реализует AwaitAttempt. Поля Progress описывают
  проверяемый и следующий этапы; один счётчик не заменяет оба смысла.
- История результата остаётся обычным immutable List. Полезные ограничения
  хранения проверяются отдельно от номеров попыток; новый History-wrapper,
  контекст или дополнительная иерархия состояний не нужны.

Подробная история завершённых проходов хранится в Git. Старые временные планы,
прежние API-сигнатуры и уже снятые запреты на README/Javadoc удалены из этого
рабочего файла: они не определяют текущую работу. Отчёты текущего прохода
находятся в `/tmp/awium-seven-hour-pass`.

### Продукт и API

- У семи bulk membership-операций удалены дублирующие varargs-перегрузки:
  doesNotContainAll, containsAny, containsExactly, doesNotContainExactly,
  containsExactlyInAnyOrder, doesNotContainExactlyInAnyOrder, containsOnly.
  Единственный вход — Collection. Например, containsAny(a, b) заменяется
  на containsAny(List.of(a, b)). Шесть prefix/sequence varargs-операций сохранены.
  README, рабочие вызовы и несовместимые примеры мигрированы. Коммит ef4332d.
- CheckedFunction, CheckedConsumer и внутренний AwaitAttempt допускают Throwable.
  Method references с throws Throwable передаются без адаптера. Callable остаётся
  стандартным входом источников и фабрик. Коммит 029403e.
- Condition хранит определение и собственные метаданные; создание исполняемых
  попыток принадлежит ConditionAwaitAttempt. Удалены шесть методов из модели
  и зависимость Condition от AttemptResult. Коммиты 4c47cc0, 3287a19.
- Preserving-определения нормализуют успешный результат в ConditionSupport:
  возвращают исходное наблюдение. Поэтому ConditionAwaitAttempt больше не хранит
  отдельную фабрику, не имеет приватного конструктора и preserving-адаптера
  с повторным разбором исходов. Preserving и selectors используют один bind;
  преобразующие условия сохраняют свой типизированный конструктор. Новых типов,
  состояний и публичных деклараций нет; суммарно минус 18 строк продукта.
  Две независимые /tmp-инъекции, отключающие нормализацию direct/factory формы,
  отклонены существующими identity-тестами; исходный код проходит оба теста.
  Это контроль тестов, а не найденные продуктовые дефекты.
  Сохранены null-диагностика, порядок валидации, lazy factories, identity,
  because, причины Throwable, interrupt boundaries и независимость сессий.
- Упрощены extraction switch и хранение единственного совпадения.
  Шесть копий вложенного поиска совпадения используют общий ValueMatching.containsAny.
  Сохраняются actual-first deepEquals, порядок обхода, short-circuit и причины ошибок.
  Коммиты 7d1a96e, 94d11ae.
- Await и ValueAwait имеют по одному конструктору полного состояния. Фабрики
  выбирают DEFAULT, общий конструктор проверяет source. Удалены два конструктора.
  Переконфигурация и тестовые входы используют тот же путь. Коммит 61dcf65.

### Отклонённые варианты

- Общий file manager javac не показал устойчивой выгоды в сравнительном запуске.
  Статический compiler cache, новое управление ресурсами и batch API не добавлены.
- Callable<? extends VALUE> у скалярной await-фабрики не устраняет capture
  в нужной comparison.because цепочке. source::call тоже сохраняет capture.
  API не менялся; новые обёртки и оси типов ради этого прототипа не добавлены.
- Отдельные awaitCollection/awaitMap без view-wrapper тоже выводят выбранный
  элемент/ключ как Object. Прототип view-entry-prototype не вошёл в продукт.
- Вывод результата AwaitResult.Satisfied из последней записи потребовал бы
  публичного downcast/новых проверок истории вместо одного поля. Вариант отклонён.
- Полное удаление семейных metadata helpers разнесло бы зависимость от definition
  по тестам. Удалены только корневые алиасы, повторявшие публичные getters.

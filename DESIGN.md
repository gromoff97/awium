## Договорённости

- Публичный API и публичное поведение разрешено менять ради общего упрощения,
  в том числе когда прежнее поведение не было дефектом. Обратная совместимость
  и переходные алиасы не требуются. Сохранять философию: проверки выражаются
  через `Condition`, пользовательский код остаётся короткой, единообразной
  и типобезопасной fluent-цепочкой. Для одной операции оставлять один способ.
- Цепочка заканчивается на `until`, возвращающем конкретный тип. Каждый вид
  условия поддерживает `because`; `present` и `single` доступны без скобок.
  Сохранять вывод типов без явных generics в поддерживаемых цепочках, запрет
  несовместимых условий при компиляции и отсутствие случайного расширения до `Object`.
- В коллекциях `contains(value)` и `doesNotContain(value)` принимают ровно один
  элемент, включая список или массив. Готовый набор передаётся через
  `containsAll(collection)` и `doesNotContainAny(collection)`. Перегрузки varargs
  для этих двух одиночных операций и переходные алиасы не нужны.
- Для Map тот же принцип: `containsKey`, `doesNotContainKey`, `containsValue`,
  `doesNotContainValue` принимают один объект; методы keys/values во множественном
  числе, включая `containsOnlyKeys`, принимают коллекцию. Четыре дополнительных
  публичных метода согласованы пользователем ради единого контракта.
- `Condition` остаётся моделью и хранит собственные метаданные. Проверка возвращает
  `Satisfied` или `Unsatisfied`; `Uncontrolled` принадлежит результату попытки.
  `AwaitAttempt.probe` проверяет полученное наблюдение; `SequenceExecution`
  управляет этапами и не реализует `AwaitAttempt`.
- Ядро обрабатывает все `Throwable` единообразно. Адаптер `asserted` преобразует
  `AssertionError` в `Unsatisfied`. Выброшенный `InterruptedException` не требует
  восстановления флага; учитывается фактический флаг потока.
- Конкретные правила последовательностей, удержания результата, обработки `null`
  и диагностики можно пересматривать, если это уменьшает общую сложность
  и сохраняет философию API. Прежние тесты сами по себе не запрещают такое изменение.
  Конфигурация, условия и структуры опубликованных результатов остаются неизменяемыми;
  пользовательские объекты сохраняют свой тип и идентичность. Рабочее состояние
  локально выполнению.
- Java 21, без новых runtime-зависимостей. Имена параметров типов — капсом.
  README и Javadoc разрешено менять и синхронизировать с кодом.
  Скиллы Java-рефакторинга не применять.

### Намеренные изменения контрактов

- `Source<T>` заменяется на `Callable<T>`, `Source.*` — на `Await.*`,
  метод источника `get()` — на `call()`. Границы структурированных источников
  сохраняют конкретные типы и wildcard-представления. Обычная запись:
  `Callable<User> source = service::loadUser;`
  `User user = await(source).until(matches(User::ready).because("ready user"));`.
- `AttemptRecord.Timing.BeforeRetrieval/BeforeObservation/AfterObservation`
  заменяются единым `AttemptRecord.Timing(start, retrieval, observation, completion)`.
  Невыполненный checkpoint равен `null`; начало и завершение обязательны.
  Пример чтения: `attempt.outcome().timing().observationOffset()`.
  Причина любой ошибки исхода читается через `attempt.outcome().cause()`;
  прежние компоненты `failure()` переименованы. Вид исхода по-прежнему различает
  отсутствие наблюдения и наблюдение `null`.
- `isNull` возвращает исходное значение своего типа; `absent` — тот же пустой
  `Optional`. `Unsatisfied` может не содержать дополнительного mismatch.
- Все таймауты имеют заголовок `Acquisition deadline elapsed`. Диагностика
  показывает фазу, время, `Condition`/`Because`, вложенные поля и полное сообщение
  причины. Имена исключений полные. Ожидаемые записи карты выводятся как `[key=value]`.
- Сравнение и вывод массивов следуют JDK. Отдельная гарантия сравнения различных
  циклических графов и глубины 50 000 удалена; ошибки становятся обычным
  `Uncontrolled` или ошибкой диагностики. `toString`, вернувший `null`, выводится
  стандартно как `null`. Половина суррогатной пары внутри целого символа больше
  не считается совпадением при поиске строки без регистра.
- Снимки коллекций и записей неизменяемы; пользовательские элементы сохраняют
  идентичность, `null` и порядок. Исходные `Throwable` не копируются и не мутируются;
  ошибки форматирования различаются по идентичности, даже если их `equals` совпадает.

### Рабочий префикс последовательности

`SequenceExecution` хранит один частный `ArrayList` завершённых этапов. Перед
повторной проверкой последнего этапа его значение удаляется; успешный probe всегда
добавляет одно значение. Полный результат публикуется отдельным неизменяемым
снимком. Дополнительного индекса, флага или класса нет. Внутренний буфер изменяем;
публичные результаты и прежние снимки остаются неизменяемыми.

Это удаляет копирование всего префикса на каждом этапе: накопление становится
линейным вместо квадратичного. В компонентном сценарии из 20 000 простых этапов
выделения памяти уменьшились с 815 до 5 МБ; это локальный замер, а не оценка
обычной нагрузки. Сохранены порядок, `null`, идентичность элементов и прежние
снимки. Совпали все 63 452 160 комбинаций независимой модели и по 17 280
параллельных сессий на версию. Полный `check`: 415 тестов.

### Независимые capture-типы между наблюдениями
